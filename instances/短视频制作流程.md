# 短视频制作流程

> 适用场景：一条短视频从选题到发布复盘的全过程。
> 输入：账号定位 + 选题方向。最终产出：发布成片 + 数据复盘。

## 流程图（文字版）

```
[选题] ──► [脚本] ──► ◎ 人工验收（脚本可改） ──► [拍摄]
   ──► [剪辑] ──► ◎ 人工验收（成片可改） ──► [分级检查] ◆
   ├── 通过 ──► [发布] ──► [数据复盘]
   ├── 可修补 ──► [修补剪辑] ──► [发布]
   └── 返修 ──► ↻ 回 [脚本] 或 [拍摄]，成片返修最多 3 轮
■ 红线：不用无版权音乐和素材；口播数据必须有来源
```

## 角色卡

- **选题策划**：goal 定出值得拍的选题。输入：账号定位 + 选题方向。输出：选题 + 理由（受众、热点、差异化）。终止：选题已定。
- **编剧**：goal 写出可拍的脚本。输入：选题。输出：脚本（画面、口播、时长、道具清单）。终止：脚本通过人工验收。
- **拍摄**：goal 按脚本拍出素材。输入：脚本。输出：原始素材。终止：素材齐全（缺镜头的要标明）。
- **剪辑**：goal 剪出成片。输入：原始素材 + 脚本。输出：成片 + 字幕。终止：成片通过人工验收。
- **运营**：goal 发布并复盘。输入：成片。输出：发布记录 + 数据复盘。终止：复盘已定稿。

## SOP 步骤表

| 步骤 | 谁干 | 输入 | 产出 | 下一步交给谁 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 1 | 选题策划 | 账号定位 + 选题方向 | 选题 + 理由 | 编剧 | 理由要讲清给谁看、为什么看 |
| 2 | 编剧 | 选题 | 脚本 | 人工验收 | 画面口播时长道具都要写 |
| 3 | 人工验收 | 脚本 | 通过 / 修改意见 | 编剧（返修）或拍摄 | 可改 |
| 4 | 拍摄 | 脚本 | 原始素材 | 剪辑 | 缺镜头要标明，不硬凑 |
| 5 | 剪辑 | 原始素材 + 脚本 | 成片 + 字幕 | 人工验收 | 字幕要校对 |
| 6 | 人工验收 | 成片 | 通过 / 修改意见 | 剪辑（返修）或运营 | 可改，返修最多 3 轮 |
| 7 | 运营 | 成片 | 发布记录 + 数据复盘 | 选题策划（下一条） | 数据对应到选题和脚本复盘 |

## 细则层

### 宽容度分级表

| 缺陷 | 分级 | 判定标准 | 处理 |
| --- | --- | --- | --- |
| 口播事实错（数据、说法无来源或错误） | 返修 | 事实核对不通过 | 返修重拍或重录 |
| 无版权音乐、素材、字体 | 返修 | 版权核对不通过 | 替换重剪 |
| 结构错（缺开头、结尾、逻辑断） | 返修 | 脚本结构缺失 | 返修重剪 |
| 字幕小错（错别字、断句） | 可修补 | 不影响理解 | 直接改字幕 |
| 剪辑小瑕疵（转场、音量轻微问题） | 可修补 | 局部小范围 | 微调重导出 |
| 封面小问题（文字、裁切） | 可修补 | 不影响识别 | 直接改 |
| 数据差 | 优化（非返修） | 数据低于预期 | 下一条改进，不返修本条 |
| 无问题 | 通过 | — | 直接发布 |

### 检查表

- [ ] 选题：受众、热点、差异化理由是否讲清？
- [ ] 脚本：画面、口播、时长、道具是否都写了？口播数据是否有来源？
- [ ] 拍摄：素材是否齐全？缺镜头是否标明？
- [ ] 剪辑：字幕是否校对？转场、音量是否检查？
- [ ] 发布前合规：音乐、素材、字体版权是否核对？口播事实是否再核对？
- [ ] 复盘：数据是否对应到选题和脚本？

### 脚本模板（结构）

钩子（开头留人）→ 正文（按要点分段）→ 结尾（总结或引导）→ 道具清单 → 时长。结构固定，内容按选题填。

### 返修原因分类

- 事实类：口播数据、说法错。
- 版权类：音乐、素材、字体无版权。
- 结构类：缺开头、结尾、逻辑断。
- 技术类：剪辑、字幕、封面问题（小问题走可修补）。

### 常见错误

- 脚本没验收就开拍。
- 字幕不校对直接发。
- 版权音乐随便用。
- 成片小错也重拍，浪费轮数。
- 数据复盘不对应到选题和脚本。

### 演示示例（纸面推演，通用选题，非真实执行）

通用选题“如何挑选无线鼠标”：选题理由讲清 → 脚本验收通过 → 拍摄缺一个镜头已标明 → 剪辑成片 → 验收发现字幕一处错别字 → 定级可修补 → 改字幕重导出 → 发布 → 复盘（数据对应到选题）。本节仅演示流程走法。

## 验收点和护栏清单

- [ ] 验收点 1：脚本人工验收后才拍摄。
- [ ] 验收点 2：成片人工验收后才发布。
- [ ] 宽容度：按分级表定级，可修补的直接改，事实、版权、结构问题必须返修。
- [ ] 禁区：不用无版权音乐、素材、字体；不编造口播里的数据。
- [ ] 事实核对点：口播数据、产品信息发布前再核对。
- [ ] 循环上限：成片返修最多 3 轮。
- [ ] 不可逆动作：发布，执行前需拍板。
- [ ] 产物落盘：选题理由、脚本、成片、数据复盘全部留档。
- [ ] 待定项：完播率、点赞率等数据合格线，需经验或平台数据补，不编造。
